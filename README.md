# 🎓 Studflow — Умный чат-бот для коммуникации студентов и сотрудников ВУЗа

**Studflow** предназначен для автоматизации рутинных запросов студентов в деканат и профильные кафедры. Бот выполняет роль первой линии поддержки (FAQ), используя **GigaChat** для моментальных ответов, и выступает в роли удобного интерфейса маршрутизации (Helpdesk) для связи с сотрудниками ВУЗа при нестандартных обращениях.

## 🚀 3. Основные пользовательские сценарии

1. **Регистрация:** Пользователь запускает бота и выбирает свою роль (Студент или Работник ВУЗа).

2. **Сценарий студента:** Студент выбирает кафедру и задает вопрос. Нейросеть *GigaChat* анализирует запрос и дает моментальный ответ по базе знаний. Если подходящего ответа в базе нет, вопрос автоматически сохраняется в очередь для живых сотрудников.

3. **Сценарий сотрудника:** Сотрудник видит очередь актуальных вопросов своей кафедры/отдела, пишет ответ прямо в чат-боте, и студент получает уведомление с решением.

## 🛠 4. Состав и архитектура решения

Решение построено на микросервисной архитектуре:

* **Бэкенд:** `Python 3.11+`, асинхронный фреймворк для Max API (`maxapi`).

* **База данных:** `MongoDB` для хранения профилей пользователей, активных сессий, очередей вопросов и базы знаний (FAQ).

* **LLM Интеграция:** `GigaChat API` (через официальный SDK `gigachat`).

### Внешние сервисы и интеграции

* **MAX API:** Внешний мессенджер, выступающий пользовательским интерфейсом. Не воспроизводится внутри локального Docker-контейнера. Бот работает по методу Long Polling, поэтому дополнительные внешние порты для входящих вебхуков открывать не требуется.

* **GigaChat API (Сбер):** Внешний облачный сервис генерации ответов. Требует активного интернет-соединения и валидного ключа.

## 🗄 6. Описание работы с данными

БД хранит три основные сущности:

* **Users** — данные регистрации (роль, ФИО, ВУЗ, группа/кафедра).

* **Queries** — вопросы студентов (статус обработки, привязка к кафедре).

* **FAQ (база знаний)** — справочная информация для контекста GigaChat.

## ✅ 7. Пошаговый сценарий проверки

1. Запустите решение (через Docker или локально `python src/main.py`).

2. Откройте мессенджер МАКС и найдите бота.

3. Зарегистрируйтесь как студент (введите данные по шаблону).

4. Задайте вопрос из FAQ (например: *"Как получить справку об обучении?"*). Убедитесь, что бот прислал быстрый ответ от GigaChat.

5. Задайте нестандартный вопрос, которого нет в базе знаний. Убедитесь, что бот ответил: *"Вопрос добавлен в очередь на рассмотрение сотрудникам"*.

6. Напишите в чат команду `su` для активации режима суперпользователя и нажмите *"Очистить мой ID из БД"*.

7. Зарегистрируйтесь как работник ВУЗа (выбрав ту же кафедру, куда был отправлен вопрос).

8. Нажмите *"Посмотреть вопросы к кафедре"*, выберите перенаправленный вопрос и ответьте на него.

### Примеры ожидаемого поведения системы

* **Успешная регистрация:** При вводе корректных данных бот отвечает *"Регистрация успешна!"* и выдает профильное меню.

* **Перехват LLM:** На шаблонные вопросы бот отвечает с префиксом *"Быстрый ответ:"*.

* **Ошибка ввода:** При вводе неверного количества полей регистрации бот уведомляет: *"Неверное количество полей... Проверьте формат ввода"*.

## ⚠️ 8. Известные ограничения

* На данный момент GigaChat обрабатывает только текстовые запросы (сообщения с вложениями или фото не поддерживаются).

* При отзыве токена MAX API или истечении бесплатных лимитов Freemium в GigaChat запросы могут возвращать ошибки на стороне сервера.
